ARCHITECTURAL FINDING: imodent_bridge.py — Cross-File Data Extracted But Never Used
================================================================================

Source: moedularizer/src/moedularizer/imodent_bridge.py

The ImodentBridge extracts cross-file dependency data that is never consumed
by moedularizer's clustering pipeline. This is a moedularizer shortcoming
(see TOOL_SHORTCOMINGS_2026-06-14.md A1), but it originates in the bridge
API design: the data is available but has no consumer.

What imodent_bridge.py extracts:
  - unused_imports: set of (module, name) tuples flagged as unused
  - import_usage: per-file ImportUsage records with usage counts
  - cross_file_deps: {importing_module: set(imported_modules)} — full project graph
  - warnings: circular dependency warnings

What moedularizer actually uses (in __init__.py:216-234):
  1. Unused import filtering in generated modules (filter_external_imports)
  2. Warning messages appended to result.warnings

What is WASTED:
  - cross_file_deps — never passed to Clusterer.cluster()
  - import_usage — never used to evaluate split impact
  - Circular dependency warnings — never fed back into clustering decisions

Evidence — __init__.py:236:
    imodent_report = bridge.analyze_project(...)   # cross_file_deps populated
    clusters = clusterer.cluster(symbols, dependencies)  # receives ONLY intra-file deps

Evidence — __init__.py:325:
    generator.generate(clusters, ..., imodent_report=None)  # hardcoded None

Impact:
  - Clusterer has no awareness of external callers
  - Safest strategy: "keep tightly-coupled things together" → single-module output
  - code_graph_engine.py (899 lines), graph_engine.py (567 lines), sq_lite_vec_backend.py (718 lines)
    all came out as single modules because clusterer couldn't evaluate external coupling

Recommended fix (for moedularizer):
  1. Pass cross_file_deps into Clusterer.cluster() as a third parameter
  2. Add external coupling scoring: for each candidate split, count how many
     external files would need import path changes
  3. Prefer splitting symbols with few external callers over symbols with many
  4. Add circular dependency prediction: before finalizing clusters, check if
     the split would create cycles with external modules

IMODENT-SPECIFIC SHORTCOMINGS
================================================================================

These are issues in imodent itself — not in how moedularizer consumes its output.

### I1: No Severity Triage

All 340 findings dumped flat. S608 (SQL injection) and S310 (URL open) are
security findings but presented identically to TRY003 (style). No "fix these
first" ranking.

Improvement: Add severity tiers: SECURITY > CORRECTNESS > STYLE. Color-code output.

---

### I2: No Fix Confidence Scoring

Every finding has `proof_state: EXTERNALLY_VERIFIED` (Ruff) or `RAW` (import
binding). No confidence score on whether the fix is safe to auto-apply.

Improvement: Score each finding: HIGH (safe to auto-fix), MEDIUM (needs review),
LOW (manual only).

---

### I3: No File-Level Aggregation

Findings listed per-line. No summary like "embed.py has 30 findings, 15 are
TRY003." Hard to prioritize which files to tackle first.

Improvement: Add `--summary` flag that groups by file, then by rule.

---

### I4: No Import Dependency Graph

Import analysis is flat (unused/duplicate/misused). No visualization of which
modules depend on which.

Improvement: Generate a dependency graph (dot/mermaid) showing import relationships.

---

### I5: No Cross-File Impact Analysis

Finds circular dependency but doesn't say what breaks. Doesn't trace which
functions are affected by a circular import.

Improvement: For circular deps, list the import chain and which symbols are at risk.

---

### I6: No Integration with CodeGraph

imodent doesn't use the codegraph for deeper analysis (call chains, community
structure). Could leverage graph centrality to prioritize findings in hot modules.

Improvement: Add `--codegraph` flag that reads `.codegraph/codegraph.db` for
priority scoring.

---

### I7: Advisory Mode is Thin

Only detects circular dependencies. No god-class detection, no long-method
detection. codegraph-ferrari's `codegraph_patterns` already finds these
(5 god classes, 30+ long methods).

Improvement: Import codegraph pattern detection into advisory mode.

---

### I8: No Auto-Fix for Missing Imports (CONFIRMED)

F821 (undefined name) is flagged but not auto-fixed even with `--force`. FIX
mode reformats but doesn't add missing cross-module imports.

Evidence: `tools.py` F821 for `_handle_codegraph_health` remained after
`imodent -r --force`.

Improvement: Add `--fix-imports` flag that adds missing imports based on
project structure.

---

### I9: No Baseline/Delta Mode

Every run is a fresh scan. No way to compare "findings before vs after a fix."

Improvement: Add `--baseline <file>` and `--delta` flags to track regression.

---

### I10: RAW Evidence Not Actionable

Import binding findings (`proof_state: RAW`) give no guidance on what to do.
"Import is not directly used, but carries intent" — what does that mean?

Improvement: For RAW findings, suggest: move to TYPE_CHECKING, add to __all__,
or delete.

---

### I11: No File-Level Scoping

`--analyze` scans the entire directory. Can't say "just check embed.py" or
"skip tests/."

Improvement: Add `--file <path>` and `--exclude <glob>` flags.

---

### I12: FINDING Count Inflation

Same finding reported multiple times when evidence comes from multiple sources
(Ruff + import binding). `embed.py:359 S310` appears once per evidence source.

Improvement: Deduplicate findings by (file, line, rule). Show evidence count
as metadata, not separate findings.
